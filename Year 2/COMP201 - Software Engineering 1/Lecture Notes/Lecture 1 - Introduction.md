## About This Module
This module is about software engineering. It is NOT about programming, although there will be some programming issues covered such as:
- Coupling
- Cohesion
- Code Structure

This is primarily because coding is covered in other modules and system failures are rarely about lack of knowledge of a programming language.

Failures are usually due to:
- Wrong or missing requirements
- Poor design
- Poor testing
- Weak risk analysis
- Bad project management
- Lack of process

So what is **software engineering**?

Engineering is making stuff, but in a structured and disciplined manner using solid approaches.

Software is:
- Code
- Data designs
- AI training models
## Modern Programming
The impact of AI in software is everywhere. AI is used for:
- Solving problems
- Generating code
- Debugging and understanding code
The human roles are now to:
- Be able to specify accurately what the code should do
- Read, verify, improve, and re-factor code

The core responsibilities of a modern programmer in the AI age are:
- Breaking massive complicated problems down into smaller logical pieces
- Designing system architecture
- Managing security boundaries
- Reviewing and verifying code
- Giving AI precise instructions, constraints and business rules so the generated code fits the real world product
## Why Software Engineering?
Software development is difficult.

It's very important to keep in mind the difference between:
- "Easy" systems - Systems made by 1 person for 1 user or a small group of users
- "Hard" systems - Systems made by multiple people for more users - Products

Techniques that work for a single person making a project do not scale up. That's why we need a structured way to organise the development of software.

The big problem is **complexity**. The complexity comes from many sources but **size** is the key one. The Linux kernel, for example, contains over 13 million lines of code. 

We need to find ways to manage this complexity.#

When software systems fail it can be very serious:
- Software controls safety critical systems
- Software protects sensitive data
- Software handles money

We need to be able to produce software which we can demonstrate has an acceptable small chance of fault.

Software should not be more complicated than it needs to be to provide its service. This can negatively affect both users and developers of software.

Also, the structure of an organisation will determine how the software is developed. Legacy systems may be worse than what is possible but if they work and are too difficult or expensive to replace then they won't be replaced.

**Conway's Law** states that the software design will mirror structure of the company that made it. For example: If a company has different teams for frontend, backend, and database then the software will have 3 different tiers that all interact with each other.

Software engineers must:
- Design requirements
- Design the product
- Implement and test
- Manage the process

## What Makes a Good Software Engineer?
Good software engineers tend to:
- Document their mistakes as to not keep making the same ones
- Focus on the product and quality over tech
- Use tried and tested approaches
- Communicate well and work well in teams
- Document their work
- Do a lot of testing
- Produce code that can be easily understood by others
- Be able to predict their productivity

The main goal of software engineers is to implement a strong **software process**. 

A software process is "A set of activities whose goal is the development or evolution of software" and the fundamental parts of it are:
- Specification
- Development
- Validation
- Evolution

Good software delivers the required functionality to the user and has a few characteristics:
- Maintainable
- Dependable
- Efficient
- Usable

There is also an ethical responsibility that comes with being a software engineer:
- They should respect the confidentiality of their employers or clients
- Should not misrepresent their level of competence or knowingly accept work with is beyond their competence
- Know the governing laws of intellectual property and protect the IP of their employers
- Not use their skills to misuse others computers
